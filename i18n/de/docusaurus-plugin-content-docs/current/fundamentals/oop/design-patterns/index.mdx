# Entwurfsmuster

## Überblick

Ein Entwurfsmuster (Design Pattern) ist eine benannte, bewährte Vorlage zur Lösung eines wiederkehrenden Entwurfsproblems in objektorientierter Software. Es ist kein fertiger Code, sondern eine Beschreibung von Klassen, ihren Verantwortlichkeiten und ihrem Zusammenspiel, die an die konkrete Situation angepasst wird.

Der Begriff geht auf das Buch *Design Patterns: Elements of Reusable Object-Oriented Software* (1994) von Gamma, Helm, Johnson und Vlissides zurück, bekannt als „Gang of Four“ (GoF). Es beschreibt 23 Muster, jeweils mit Name, gelöstem Problem, Lösung und Konsequenzen.

Muster liefern ein gemeinsames Vokabular: „Die Preisanzeige ist ein [Observer](./observer.md) des Börsentickers“ sagt einem anderen Entwickler, dass der Ticker eine Liste registrierter Anzeigen führt und jede davon bei jeder Kursänderung benachrichtigt, ohne diese Struktur ausdrücklich zu beschreiben.

Ein Entwurfsmuster löst ein Problem innerhalb einer Klasse oder weniger zusammenarbeitender Klassen. Probleme, die die Struktur einer ganzen Anwendung betreffen, lösen Architekturmuster wie MVC, Schichtenarchitektur oder Microservices.

## Häufige Fehler

1. **Muster ohne Problem:** Ein [Strategy](./strategy.md)-Interface mit nur einer Implementierung oder eine [Factory](./factory-method.md), die immer nur eine Klasse erzeugt, bringt zusätzliche Klassen und Indirektion ohne Nutzen.
